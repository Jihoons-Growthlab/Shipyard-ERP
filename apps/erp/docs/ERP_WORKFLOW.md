# ShipYard ERP 화면별 업무 매뉴얼

## 호선 한 척의 업무 흐름

1. **기준정보·설계** — 호선, 블록, 작업장, 창고, 장비, 자재, 공급업체와 선석을 등록합니다. 블록에 적용할 도면 리비전을 기록합니다.
2. **대일정** — 호선의 착공·기공·진수·시운전·인도 기준일과 예정일을 등록합니다. 기공~진수 도크 점유와 진수 후 선석을 잡고 배치 위험을 확인합니다.
3. **중일정** — 선체 담당자는 블록 구성과 탑재 순서를, 의장 담당자는 구역별 작업과 선행 관계 및 안벽 이동을 계획합니다. 두 계획은 병행하며 대일정 변경 시 함께 점검합니다.
4. **소일정·자재** — 12주 계획을 발행하고 주간·일일 지시를 연결합니다. 작업장 제약과 크레인 배정을 확인합니다. 자재 담당자는 필요한 날짜와 수량을 기준으로 MRP를 확인하고 부족분을 구매·입고합니다.
5. **현장 실행·품질** — 지시에 자재를 출고하고, 강재 로트를 출고에 배정합니다. 조립·의장 작업과 공수를 기록하고 작업 검사 및 입회 검사를 처리합니다. 불합격은 NCR과 재검사로 관리합니다.
6. **이동·탑재** — 블록 준비 현황을 확인하고 이동을 시작합니다. 실제 도착 후 이동을 확정하고 별도로 탑재 검사 실적을 등록합니다. 선행 블록의 합격 기록을 다음 블록의 준비 판정에서 확인합니다.
7. **진수·안벽·인도** — 주요 일정 실적과 안벽 이동 실적을 각각 등록합니다. 의장품 검사, 입회 검사, 미결 NCR·펀치와 시운전 준비를 확인한 뒤 인도 실적을 등록합니다.

로그인 후 상단의 **조회 호선**을 먼저 선택합니다. 목록에서 문서번호 또는 행의 **다음 작업**을 누르면 연관 문서나 후속 입력 화면으로 이동할 수 있습니다. 검색 결과가 비면 호선·기간·검색 조건을 확인합니다. 등록 버튼은 소속 그룹의 등록 권한이 있을 때 표시됩니다.

## 화면별 사용법

### 업무 홈

**처리할 업무**

자재 부족, 미입고, 작업·이동, NCR·펀치, 일정 위험을 보고 카드나 대기 행에서 담당 메뉴를 엽니다.

### 계획

**대일정**

| 화면 탭 | 입력하거나 확인할 내용 |
|---|---|
| 호선 주요 일정 | 호선·일정별 기준일과 예정일을 등록합니다. 일정 변경이나 실제일 입력 시 변경 사유를 남깁니다. |
| 배치·위험 점검 | 도크·선석 누락, 대일정 범위와 하위 일정 위험을 확인합니다. |
| 도크 점유 예약 | 호선·도크·점유 기간을 지정합니다. 같은 도크의 중복 점유를 확인합니다. |
| 선석 배정 | 호선·선석·기간·목적을 정합니다. 등록된 선박 길이와 선석 길이 및 기간 중복을 확인합니다. |
| 일정 변경 이력 | 예정일·실제일 변경 기록에서 지연 사유를 확인합니다. |

**중일정 · 선체**

| 화면 탭 | 입력하거나 확인할 내용 |
|---|---|
| 탑재 계획 | 호선 블록의 목표 시설과 탑재 예정일을 지정합니다. |
| 탑재 선후행 | 선행·후행 블록을 연결합니다. 같은 호선의 순환 연결은 저장할 수 없습니다. |
| 블록 구성 | 상위 블록과 구성 블록을 연결합니다. |
| 탑재 일정 제안 | 제안 탑재일·크레인과 보류 사유를 비교합니다. 적용 여부는 계획 담당자가 판단합니다. |
| 주간 크레인 부하 | 주간 배정 건수와 작업 시간을 보고 과부하 여부를 검토합니다. |
| 블록 준비 현황 | 블록 행을 펼쳐 도면·자재·조립·의장·도장·검사·시설·이동의 근거와 선행 블록을 확인합니다. |

**중일정 · 의장·안벽**

| 화면 탭 | 입력하거나 확인할 내용 |
|---|---|
| 구역별 의장 진척 | 구역·공종별 현재 계획 대비 기성 공수와 지연을 봅니다. |
| 의장 작업 | 호선·구역·공종·단계·기간·공수·상태를 입력합니다. 완료 상태와 100% 진척을 함께 저장합니다. |
| 작업 선후행 | 같은 호선의 의장 작업을 선행과 후행으로 연결합니다. |
| 안벽 이동 계획·실적 | 도크·선석·해상 지점 중 출발·도착을 선택하고 목적, 계획일, 실제일을 기록합니다. |
| 선석 점유 현황 | 선석별 점유 기간과 배정 적합성 표시를 확인합니다. |

**소일정 (주간·일일)**

| 화면 탭 | 입력하거나 확인할 내용 |
|---|---|
| 12주 롤링·주간 발행 | 시작 월요일을 선택해 12주 발행본을 만듭니다. 발행본을 열어 공정별 작업지시를 연결합니다. |
| 공정 목록 | 호선·블록·공정의 기준일과 예정일을 등록하고 지연 시 예정일과 사유를 갱신합니다. |
| 제약 일정 제안 | 작업장, 자재, 선행 제약을 반영한 제안일과 보류 사유를 검토합니다. |
| 작업 제약 | 공정별 워크센터, 소요시간, 가장 이른 착수일과 선행을 입력합니다. |
| 추가 선행 공정 | 기존 작업 제약에 필요한 선행 공정을 추가합니다. |
| 크레인 작업 배정 | 크레인·호선·블록·일자·시작 시각·시간·하중을 입력합니다. 중복 시간과 정격하중 오류를 확인합니다. |

**자재 소요계획 (MRP)**

| 화면 탭 | 입력하거나 확인할 내용 |
|---|---|
| 자재 부족 | 소요일별 부족 수량과 공급 근거를 확인하고 부족 행에서 구매요청을 엽니다. |
| 공정 자재 소요 | 공정과 품목, 필요 수량, 소요일을 등록합니다. |
| 수동 입고 예정 | 예정 입고를 입력합니다. 실제 창고 재고는 합격 입고와 수불부에서 확인합니다. |

| 입고·검수 | 발주·창고·실제 입고일·수량·검수 결과를 입력합니다. 합격분만 재고에 반영됩니다. |

**자재 출고**

| 자재 출고 | 주간 작업지시·동일 공정 소요·출발 창고와 수량을 선택합니다. |
| 수불부 | 품목·창고·일자로 입고, 출고, 잔재 등을 조회하고 원천 문서를 확인합니다. |
| 창고 재고 | 창고별 가용 수량을 확인합니다. |

| 도크 선체 배치 | 도크나 야드에서 호선이 놓일 위치와 방향을 지정합니다. |
| 탑재 순서(트윈) | 형상과 탑재 순서 데이터를 확인합니다. 물류 이동 이력 및 탑재 검사 기록은 각 업무 메뉴에서 봅니다. |

## 연동 화면

- **지도** — SIWS의 조선소 지도 메뉴에서 야드 시설 위치를 확인합니다. 표시 위치가 다르면 **형상·배치**에서 부지 원점, X축 방위각, 시설 좌표를 확인합니다.
- **Swagger** — 서버의 `/docs`에서 로그인 API를 실행한 후 Bearer 토큰으로 그룹 권한 범위의 API를 확인합니다. 등록 API를 실행하면 DB에 기록됩니다.

## 조선소 업무 적합성 점검

| 점검 항목 | 확인 결과와 적용 조건 |
|---|---|
| 블록 건조 순서 | 절단·가공, 블록 조립, 선행의장·PE, 탑재, 진수, 안벽 의장·시운전, 인도의 큰 흐름은 상선 신조 공법과 맞습니다. 조립과 선행의장은 블록별로 병행될 수 있으므로, 호선 전체에 한 줄짜리 순서를 강제하기보다는 블록과 작업 단위로 선후행을 관리하는 편이 적합합니다. [대선조선 건조 공정](https://www.daesuns.co.kr/daesun/english/product05.html) · [GAO 상선·함정 건조 공정 비교](https://www.gao.gov/assets/a289537.html) |
| 계획 계층 | 대일정의 도크·선석, 중일정의 블록·의장, 소일정의 사람과 설비가 수행할 작업을 구분한 구조는 적합합니다. 의장 선행 미완료 착수와 대일정 범위 초과는 조회 경고로 표시됩니다. 예를 들어 선행 의장 범위를 기공 후 14일까지로 잡는 규칙은 이 ERP의 설정된 판단 기준이므로 현장 기준과 맞춰야 합니다. |
| 착수와 완료의 근거 | 자재 출고, 이동 확정, 작업 검사, 탑재 합격을 서로 다른 기록으로 남깁니다. 주요 일정 실적도 별도로 등록합니다. 현장 시범 적용 시 담당자와 기록 시점, 검사 증빙의 원천을 확정할 필요가 있습니다. |
| 자재 추적 | 입고·출고·로트 관계를 관리하며 로트 미배정 출고는 추적 화면에 표시됩니다. 강재 추적이 필수인 현장은 미배정 상태를 언제까지 해소해야 하는지 종료 기준을 정해야 합니다. |
| 설비·안벽 계획 | 크레인 정격하중과 시간 중복, 선석 길이와 기간 중복을 확인할 수 있습니다. 화면의 일정 제안과 수치 점검만으로 실제 인양·안벽 이동 승인에 필요한 현장 검토가 완료되지는 않습니다. |
| 의장 데이터 간 연결 | 의장 작업의 진행률과 의장품의 입고·설치·검사는 별도 화면에서 기록합니다. 대일정 검토 때 두 화면의 결과를 함께 확인해야 합니다. |

**판정** — 상선 신조의 생산계획·실행·품질·물류를 연결하는 구조로 적합합니다. 특정 조선소의 운영 적합성은 실제 호선 한 척으로 일정 기준, 승인 절차, 자재 추적 마감과 설비 운용 조건을 대조한 뒤 판단할 수 있습니다.

### 실습에서 맞는지 확인하는 방법

1. **SN2036 준비 점검** — 중일정 · 선체에서 211P 블록 구성과 선행 블록을 확인합니다. 준비 현황의 보류 사유를 열고 조립·도면·자재·품질 중 어떤 근거가 필요한지 확인합니다.
2. **H101 자재 실행** — 실습 DB에서 MRP 부족 → 구매요청 → 발주 → 입고 검수 → 주간 지시 출고를 진행합니다. 합격 입고만 재고에 더해지고 출고는 해당 창고 잔량을 줄이는지 수불부에서 대조합니다.
3. **탑재 분리 확인** — 블록 이동 확정 후 블록 위치가 바뀌는지 확인합니다. 탑재 합격 기록은 블록 위치와 별도로 관리되며 다음 블록의 선행 조건에서 확인합니다.
4. **계획 예외 확인** — 같은 크레인의 중복 시간이나 같은 선석의 중복 기간을 입력해 저장 거절을 확인합니다. 의장 작업을 대일정 범위 밖에 잡고 점검 경고가 표시되는지 확인합니다.

이번 문서 검토에서는 메뉴 정의와 저장·판정 로직을 대조했고, SQLite 자동 테스트 23건이 통과했습니다. 위 실습 시나리오는 브라우저에서 현장 담당자가 수행할 확인 절차입니다.

### 가상 호선 3척으로 확인하기

상단 **조회 호선**에서 아래 ID를 선택합니다. 세 호선은 같은 도크, 크레인, 선석을 서로 다른 기간에 사용합니다. 각 호선의 대표 블록은 3개입니다.

| 호선 | 시작 화면 | 확인할 결과 |
|---|---|---|
| FLEET-01 해솔 | 대일정 → 호선 주요 일정 | 인도 실제일이 있고 블록 3개가 탑재 완료입니다. 강재 추적에서 합격 입고와 히트번호가 출고에 연결됩니다. 품질 검사에서 재검사로 종결한 NCR과 펀치를, 중일정 · 의장·안벽에서 진수 후 이동부터 인도 출항까지 실제일을 확인합니다. |
| FLEET-02 해온 | 중일정 · 선체 → 블록 준비 현황 | B01은 탑재 완료입니다. B02는 ITP 불합격과 미결 NCR로 보류이고, B03은 B02의 탑재를 기다립니다. 크레인 배정은 계획이며 실제 탑재는 검사 기록에서 확인합니다. |
| FLEET-03 해람 | 자재 소요계획 (MRP) → 자재 부족 | 구매·입고 화면에는 부분 입고 발주와 미입고 발주가 하나씩 있습니다. 발주가 없는 소요는 후판 12장 부족으로 표시됩니다. 탑재와 안벽 이동은 계획만 있습니다. |

다른 실습 환경에서 이 세 호선을 만들려면 PostgreSQL은 `./shipyard-postgres seed_fleet.py`, SQLite는 `python3 -B seed_fleet.py --db fleet-demo.sqlite3`를 실행합니다. 같은 세 호선이 있으면 재등록을 건너뜁니다. 일정은 첫 적재 주의 월요일을 기준으로 생성됩니다.
