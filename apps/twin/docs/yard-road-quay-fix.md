# 도로와 안벽 접합 수정

ShipyardTwin Unity 화면에서 도로가 도크·수면·위성 지형으로 튀어나오는 구간과, 육지에서 의장 피어로 이어지는 접합부를 수정한다. 첨부 3장은 현재 증상에 대한 참고 화면이다.

## 화면별 요구사항

1. **도크 주변** — 선박과 도크를 가로지르는 것처럼 보이는 도로가 있다. 위에서 내려다보며 차도, 차선, 크레인 레일을 구분한다. 도로와 차량 경로를 육상 통로로 옮기고, 도크 개구부와 레일을 불필요하게 횡단하지 않게 한다.
2. **안벽 입구** — 육지에서 나온 도로 끝이 수면에 걸리고 의장 피어와 떨어져 있다. 접속부를 육상 포장면에서 피어 데크까지 이어 차량이 통과할 수 있게 한다. 연결부의 상판 높이를 맞추고, 해수면 아래까지 측벽을 내려 틈이나 떠 있는 면이 보이지 않게 한다. 도크 입구와 접안 수역은 확보한다.
3. **포장면 외곽** — 도로 조각과 가로등이 포장 경계 밖 위성 지형에 남는다. 진입로는 실제로 연결되는 구간을 확보하고, 나머지는 차도 폭과 끝부분을 포함해 포장면 안에서 끝나게 한다. 가로등과 차량도 같은 경계를 기준으로 배치한다.

## 읽을 파일과 확인 순서

- 먼저 `pipeline/generate_scenery.py`의 도로·차량 경로·소품 배치와 `unity/Assets/ShipyardTwin/Runtime/Yard/YardScenery.cs`의 `BuildRoad`를 확인한다. 도로 표면이 중심선 양끝을 넘어가므로 차선과 포장면을 실제 렌더링 폭·길이로 검사한다. 차량 루프의 마지막 점에서 첫 점으로 연결되는 구간도 검사한다.
- 안벽은 `unity/Assets/ShipyardTwin/Runtime/Yard/YardEnvironment.cs`의 `BuildGround`, `SiteOutline`, `Revetment`, `BuildFacility`에서 확인한다. 지형의 절단 범위도 바뀌는 경우에만 `SatelliteGround.cs`를 읽는다.
- 좌표를 조정하기 전에 현재 Unity가 읽는 호선 데이터의 시설만 확인한다. 도로는 `pipeline/generate_yard.py`의 기본 시설 좌표에서 생성되고, 안벽은 ERP에서 내보낸 시설 좌표로 생성되므로 `DT-DOCK`, `GY-DOCK2`, `GY-PIER`의 위치·크기·방향을 비교한다. 시설 원본 좌표 변경이 필요하면 ERP와 Unity 내보내기까지 일관되게 반영한다.
- `CLAUDE.md`의 생성 흐름을 따른다. 도로·차량·소품은 원본 생성 코드를 수정하고 `python3 pipeline/generate_scenery.py`로 갱신한다. 씬·프리팹은 기존 생성 절차를 사용한다.

## 완료 기준

- 위에서 본 화면에서 차도·차선·차량 경로가 도크 내부, 수면, 포장되지 않은 지형에 들어가지 않는다. 차량이 교차로와 회차 구간을 따라 움직인다.
- 안벽 접속부를 가까이서 봤을 때 육지 포장면과 피어 상판이 이어지며 틈, 높이 단차, 겹침 깜빡임이 없다. 연결부가 도크 입구를 막지 않는다.
- 경계 밖에 떠 있던 도로 조각과 가로등이 없다.
- Unity Play Mode 또는 `tools/capture.sh`로 조선소 전경, 안벽 접합부, 도로 외곽을 확인한다. 런타임 코드를 수정했다면 `tools/test.sh`도 실행한다. 결과에는 재생성한 데이터와 확인한 화면을 적는다.
