# ShipyardTwin 성능 측정 인수인계

Claude Code 사용량 제한 전에 원시 결과가 `docs/perf/results/`에 복사됐다. 이 문서는 기존 결과만 정리했다. 원시 결과는 기존 ShipyardTwin 작업 폴더에 보관돼 있다.

## 전후 비교 한 쌍

`s-baseline-2`와 `s-after-2`의 로그·JSON을 비교했다. 둘 다 1600×900이며, 기준 로그에 SN2040 138블록, 변경 로그에 스냅샷 1호선 138블록 및 SN2040 선택이 기록돼 있다. 변경 빌드는 호선 선택 시 상세 메시를 로딩한다. 호선과 블록 수는 확인했으며, 양쪽 씬 상태와 측정 구간이 완전히 동일한지는 확인하지 못했다.

| 지표 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 대기 프로세스 CPU | 48.8% | 61.7% |
| 재생 프로세스 CPU | 60.0% | 124.8% |
| 대기 렌더 스레드 평균 | 1.471 ms | 2.667 ms |
| 재생 렌더 스레드 평균 | 3.585 ms | 4.431 ms |
| 대기 Unity 사용 메모리 | 248.4 MB | 211.6 MB |
| 재생 Unity 사용 메모리 | 250.8 MB | 250.5 MB |

이 한 쌍에서는 대기 메모리가 감소했고 CPU와 렌더 스레드 비용은 증가했다. 변경 빌드의 호선 선택 로딩은 2.251초였으므로, 재생 CPU 차이의 원인을 판단하려면 프로세스 표본 구간에 로딩이 포함됐는지 먼저 확인한다. 스냅샷 인자가 누락된 이전 측정은 비교에서 제외한다.

## 기능 검증 및 다음 작업

Claude Code 작업 로그 기준으로 EditMode 19개, Play Mode 4개 통과. 샌드박스 ERP 조회와 SN2046의 2도크 인양을 확인했다. 전체 조합 재측정은 보류한다. 이어서 작업할 경우 먼저 저장된 `s-baseline-2`와 `s-after-2`의 JSON·로그·프로세스 표본을 사용한다.
